# AGENTS.md

Guidance for agents maintaining and developing this repository: a personal
NixOS + Home Manager flake ("nix-files"). Read this before making changes.

## Architecture

Single flake ([flake.nix](flake.nix)) with these outputs:

- `nixosConfigurations.albemuth`, `nixosConfigurations.makondo` — full NixOS
  systems, built by the local `mkNixos` helper. Each wires together:
  per-host module setting `user.*` options →
  `home-manager.nixosModules.home-manager` → `machines/<host>/` →
  [default-configuration.nix](default-configuration.nix) (shared base).
- `homeConfigurations."atsoukka"` — standalone Home Manager via
  [home-configuration.nix](home-configuration.nix) for non-NixOS hosts
  (single-user Nix, e.g. RHEL).
- `overlays.default` — adds `pkgs.unstable` (nixpkgs master) everywhere.
- `formatter.x86_64-linux` — `nixfmt` (invoked by `nix fmt`).

Key contracts — do not break these:

1. **Custom `user.*` options.** `user.name`, `user.description`, `user.home`
   are declared in [modules/nixos/env-user.nix](modules/nixos/env-user.nix)
   and set per host in `flake.nix`. Many modules reference
   `config.user.name` (env-base, env-nix, hw-yubikey, services-xmonad,
   services-virtualization). New NixOS modules needing the username must use
   `config.user.name`, never a hardcoded string.
2. **Shared Home Manager module list.**
   [modules/home/default.nix](modules/home/default.nix) is a plain **list of
   paths** (not an attrset, not a module). It is consumed both by
   `default-configuration.nix` (home-manager as a NixOS module) and by
   `home-configuration.nix` (standalone). Every module in it must evaluate in
   both contexts — avoid NixOS-only options there.
3. **home-manager as NixOS module.** [modules/nixos/env-base.nix](modules/nixos/env-base.nix)
   sets `home-manager.useGlobalPkgs = true`, `backupFileExtension = ".bak"`,
   and `home.stateVersion = config.system.stateVersion`. Standalone HM sets
   its own `home.stateVersion` in `flake.nix`.
4. **No `nixpkgs.config` inside Home Manager modules.** HM ignores it both
   with `useGlobalPkgs` (NixOS) and with an externally supplied `pkgs`
   (standalone). Unfree allowances live in `flake.nix` (standalone
   `allowUnfreePredicate`) and `modules/nixos/env-base.nix`
   (`allowUnfree = true`).
5. **The user session belongs to Home Manager.** On NixOS,
   `modules/nixos/services-xmonad.nix` only registers the
   `none+xmonad` session (lightdm) and does system-level setup; that
   session executes the `~/.xsession` generated by
   `modules/home/services-xmonad.nix` (`xsession.enable = true`), which
   starts the HM-compiled xmonad and the HM-managed tray applets and
   screen locker. Never spawn session tools from NixOS
   `sessionCommands` — they would run twice.
6. **flake-compat.** [default.nix](default.nix) and [shell.nix](shell.nix)
   are `flake-compat` shims so non-flake commands keep working; the
   `flake-compat` input is pinned in `flake.lock`. Keep them as-is.

## Conventions

- **Module naming:** `<area>-<name>.nix` with prefixes `env-` (base system
  environment), `hw-` (hardware support), `programs-`, `services-`.
  `modules/nixos/` holds NixOS modules, `modules/home/` Home Manager modules;
  some areas exist in both trees (e.g. `programs-obs`, `services-fineid`).
- **Machines:** `machines/<host>/default.nix` imports `generated.nix` +
  `manual.nix`. `generated.nix` is `nixos-generate-config` output — **never
  hand-edit it**; regenerate instead. All hand-maintained host config goes in
  `manual.nix`.
- **Loose assets** live next to modules (`modules/services-xmonad.hs`,
  locale/editorconfig conf files) and are referenced from the corresponding
  module.
- **State versions:** `system.stateVersion` (per machine, `manual.nix`) and
  `home.stateVersion` are set intentionally. Never bump them as part of an
  unrelated change.
- **Formatting:** all `*.nix` are formatted with `nixfmt` (RFC style). Run
  `make format` before committing.
- **Commits:** short imperative messages; conventional prefixes
  (`refactor:`, `chore:`) are used occasionally. See `git log`.

## Common tasks

- **Add a Home Manager module:** create `modules/home/<area>-<name>.nix` and
  append its path to the list in `modules/home/default.nix`. Verify it works
  in both NixOS-HM and standalone HM contexts.
- **Add a NixOS module:** create `modules/nixos/<area>-<name>.nix` and add it
  to `imports` in [default-configuration.nix](default-configuration.nix).
- **Add a machine:** see README ("Adding a new machine"); add a
  `nixosConfigurations` output via the `mkNixos` helper in `flake.nix`
  (it sets the required `user.*` options).
- **Use an unstable package:** reference `pkgs.unstable.<name>`; the overlay
  is applied to every configuration.
- **Update inputs:** `nix flake update` (or `--update-input <name>`). nixpkgs
  and home-manager release branches must stay in sync (both currently
  `26.05`).

## Verification

Always validate changes before considering them done:

```console
$ make check        # nix flake check — evaluates all outputs
$ make format       # nixfmt everything
```

For system changes, additionally build without switching:

```console
$ nix build .#nixosConfigurations.albemuth.config.system.build.toplevel
$ nix build .#homeConfigurations.\"atsoukka\".activationPackage
```

Deployment (`make "switch <host>"` — target names contain a space) is done by
the user on the actual machine; do not run `nixos-rebuild switch` yourself.

## Gotchas

- Makefile targets `switch albemuth|makondo|atsoukka` contain a literal
  space; quote them when invoking.
- `home-manager switch` attrpath is `.#homeConfigurations.atsoukka` (quote
  the attr in shells that need it).
- The standalone HM config forces its own `.Xmodmap` and HiDPI xresources —
  be careful when touching [home-configuration.nix](home-configuration.nix).
- `documentation.nixos.enable = false` and channels are disabled globally;
  don't reintroduce channel-based patterns.
- `.gitignore` excludes `/deprecated/` (old experiments, ignored on purpose).
